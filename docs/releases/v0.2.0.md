# acct-sh v0.2.0

acct keeps one GitHub account, one git identity and one directory tree together.
This release closes the ways the wrong account could still be used, makes acct
safe to install next to your existing git setup, and tells you plainly when
something isn't protected.

**After upgrading, run `acct install` once.** It regenerates acct's git includes
and hooks. Your profiles and bindings carry over unchanged.

## Highlights

### gh no longer falls back to another account

Before 0.2.0, `gh auth switch` or `gh auth login` in any folder could leak into a
bound folder. If acct couldn't confirm the token for the folder's account (for
example, offline or rate-limited), it cleared `GH_TOKEN`, and gh silently used
its global active account.

Now acct always uses the token gh holds for the folder's account, with no network
call on `cd`. If no token exists at all in a `strict` folder, gh is blocked there
(it fails with a 401 and acct prints the fix) instead of acting as someone else.

### Commits and pushes are checked against what git actually records

- The commit check now looks at the author and committer git will really write.
  Before, it only checked `user.name`/`user.email`, so `GIT_AUTHOR_EMAIL=…` or
  `--author` slipped through.
- Merge commits are checked too (`pre-merge-commit`).
- `pre-push` re-checks the author and committer of every outgoing commit.
- `pre-push` verifies the account the push will actually authenticate as, over
  HTTPS or SSH. SSH is verified from GitHub's `Hi <user>!` greeting, so a wrong
  key from your SSH agent or `~/.ssh/config` is caught.

### Plays well with the rest of your git setup

- acct's credential helper is now scoped to the GitHub hosts in your profiles.
  GitLab, Bitbucket and other HTTPS hosts keep their own helpers.
- Hooks install globally and **chain to your existing hooks**. A repository's own
  `.git/hooks` and a previous `core.hooksPath` (Husky etc.) keep running, and new
  clones under a bound folder are covered automatically. Use `acct install --repo`
  where a repository sets its own local `core.hooksPath`.
- `~/.gitconfig` is written using git's own lock file. Symlinked dotfiles stay
  symlinks, and file permissions are preserved.
- `acct uninstall` restores the hooks path you had before.

### Git and acct always agree on the profile

- Every part of acct resolves the profile from the repository root, the same way
  git applies its `includeIf` identity.
- Nested bindings are written in the right order, so the most specific folder wins.
- Symlinked and differently-cased paths match.
- A linked worktree that would get a different account from git than from its
  folder binding is refused in `strict` mode.
- `.acct` files below a repository root are ignored and reported.
- `acct local set <profile>` marks a single repository and makes git's identity
  match.

### Safer secrets and config

- Credential-helper errors stop git from trying other helpers. Before, a corrupt
  file could let a later helper answer.
- Plaintext token copies (`secrets.json`, `secrets.json.bak`) are moved into the
  OS keychain and deleted.
- Removing one profile no longer deletes a token or SSH key another profile shares.
- Error messages never echo secret-file contents.
- Concurrent acct commands no longer lose each other's changes. A failed `init`,
  `install` or `bind` rolls back completely, and a lock left by a crashed process
  is recovered.
- The config file is validated on load, with errors that name the bad field.
  Mistyped flag values like `--enforce strcit` are rejected.

### Clearer diagnostics

- `acct status` and `acct doctor` now warn when:
  - the shell hook isn't loaded in your current shell
  - a bound folder no longer exists (moved or deleted)
  - acct's generated helper or hooks point at a node or acct path that's gone
- They only say a commit or push "will be refused" when acct's hook is actually
  active in that repository.
- `acct doctor` reports any other credential helper that would answer before acct.
- `acct whoami` exits `0` match, `1` mismatch, `2` unknown.

## New commands

| Command | Use |
|---|---|
| `acct rebind <old> <new>` | Move bindings after you move or rename a folder |
| `acct local set <profile>` / `--unbound` / `clear` | Mark one repository and align its git identity |
| `acct install --repo` | Install hooks for a repository whose local `core.hooksPath` overrides the global one |
| `acct_refresh` (shell function) | Re-read acct's settings in an open shell |

## Other fixes

- `acct exec gh --version` and other child flags now reach the child command, not
  acct. The optional `gh` wrapper no longer calls itself in a loop.
- `gh auth --hostname github.com token` and `gh auth status --show-token` are
  blocked under `acct exec`, like `gh auth token`.
- Switching from an Enterprise profile to github.com no longer leaves `GH_HOST`
  pointing at Enterprise.
- Fish gets native `set -gx`/`set -e` output. A failed shell refresh clears
  acct's variables instead of keeping the previous folder's token.
- GitHub usernames are compared case-insensitively everywhere.
- Names like `Alice # Team` and paths with quotes are written to git config
  correctly.
- The setup wizard stops on Ctrl-D/Ctrl-C without changing anything, and keeps
  the flags you passed.

## Behaviour changes to know about

- **Hooks are installed globally by default.** Because acct chains to your existing
  hooks, this no longer disables them. `--global` is still accepted.
- **`git commit --author=…` is caught at push, not at commit time** (git doesn't
  expose `--author` to `pre-commit`). Commits in repositories that are never
  pushed aren't re-checked.
- **`.acct` markers below a repository root are ignored.** Move them to the root
  with `acct local set`.
- **Bash refreshes at the next prompt.** In `cd repo && gh …` on one line, gh runs
  before the refresh. Use `acct exec -- gh …` or the gh wrapper when that matters.
- **A credential-helper section added after acct's block wins.** That's exactly
  what `gh auth setup-git` can append. `acct doctor` reports it, and `acct install`
  puts acct back last.

## Install

```sh
npm install -g acct-sh@0.2.0
acct install
```

Then add the shell hook to your shell's startup file (see
[shell/README.md](https://github.com/abdull-ah-med/acct/blob/v0.2.0/shell/README.md)),
for zsh:

```sh
echo 'command -v acct >/dev/null && eval "$(acct hook zsh)"' >> ~/.zshrc
```

Also on GitHub Packages as `@abdull-ah-med/acct-sh@0.2.0` (same `acct` and
`git-credential-acct` commands). The package tarballs and their SHA-256 checksums
are attached to this release.

## Limits

Client-side hooks can be bypassed (`--no-verify`, a custom `core.hooksPath`); use
server-side rules where enforcement must be mandatory. acct verifies accounts
against GitHub's responses; it doesn't sandbox programs you run under `acct exec`.
