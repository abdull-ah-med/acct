# acct-sh v0.1.13

This patch corrects Windows directory-binding validation and makes the
cross-platform test harness execute native command fixtures. It also improves
release notes and checks publication in both supported registries.

## Changes

- **Windows paths:** initialization, binding, and generated include installation
  accept native absolute drive and UNC paths. Unsafe control characters, quotes,
  brackets, and wildcard patterns remain rejected.
- **Cross-platform verification:** behavioral tests use native gh/git command
  fixtures instead of relying on POSIX scripts or `.cmd` execution. Production
  child processes continue to execute without introducing a shell.
- **Release process:** explicit version-tag validation, versioned release notes,
  and checks that both registries contain the requested package version.

## Installation

From npm:

```sh
npm install -g acct-sh@0.1.13
acct --version
```

From GitHub Packages, after configuring registry authentication and the
`@abdull-ah-med` scope:

```sh
npm install -g @abdull-ah-med/acct-sh@0.1.13
acct --version
```

Both packages provide the `acct` and `git-credential-acct` binaries. There is no
configuration-schema migration in this release. Existing profiles and bindings
are retained.

## Scope and limitations

This release addresses Windows compatibility and publication verification. The
separate project-wide review identified additional identity, credential,
secret-lifecycle, and shell-integration issues that remain open. This patch
should not be interpreted as resolving those findings. Client-side hooks also
remain bypassable; server-side controls are required for mandatory policy.
