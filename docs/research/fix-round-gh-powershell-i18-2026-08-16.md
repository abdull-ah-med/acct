## Design chosen

1. **`gh auth token --hostname --user` is the documented read of a stored account token** — not of PATH, not of a login string. Callers that invoke the binary as the name `"gh"` use **PATH** (Node). `GH_PATH` is unrelated. Cite: gh_auth_token; gh_help_environment; Node child_process.

2. **Strip env tokens before `gh auth token --user`** (already done). `GH_TOKEN` / `GITHUB_TOKEN` take precedence over stored credentials; `auth login` / `logout` / `refresh` refuse to mutate the keyring until the env value is cleared. `gh auth token` can still print *a* token while the env override is set (discussion#9647). Cite: gh_help_environment; cli#2922; discussion#9647.

3. **Do not persist untrusted PATH `gh` stdout into the OS keychain without a principal check.** `--user alice` is an argument to whatever binary PATH resolved. A fake `gh` can ignore `--user` and print an attacker token. After a live token is obtained, verify with `gh api user --jq .login` (documented `gh api` + REST `GET /user` required `login`) **using that token** (`GH_TOKEN=<live>` so the API call authenticates as the token, not a sticky env). Persist / inject only if `login` equals the profile `githubUser` (case-fold per I19). On mismatch or API failure: do **not** write the keychain; fall back to the previously stored profile token (or fail closed on `--import-gh`). Pinning an absolute `gh` path is **not** required by gh or Node docs; PATH is the documented lookup for an unqualified name. Optional hardening (not a substitute for the principal check): resolve `gh` via `process.env.PATH` once and refuse if the resolved path is not a regular file. Cite: Node PATH lookup; GET /user; gh_api; gh_auth_token.

4. **I18 fail-closed for PowerShell opaque script carriers** — a deny-list that cannot decode EncodedCommand must refuse the flags that run arbitrary script whose body is invisible at argv-inspect time (same rationale as xargs stdin / decoder\|shell):
   - `pwsh` / `powershell` / `pwsh.exe` / `powershell.exe`: refuse `-EncodedCommand`, documented aliases `-e` / `-ec`, and unique-prefix / case-insensitive forms including **`-enc`** (plaintext `gh auth` is UTF-16LE Base64; Microsoft’s own decoder reads CommandLine for the string `EncodedCommand` then Base64-decodes Unicode).
   - Refuse **`-File` / `-f`** (and `-File -` stdin): the script lives in a file / stdin, not in argv.
   - Keep scanning `-Command` / `-c` / `-CommandWithArgs` / `-cwa` plaintext (already in I18).
   - `cmd` `/c` / `/k`: if the command string contains `pwsh`/`powershell` plus an opaque carrier above, refuse (cmd only “carries out the command specified by string”; it does not decode EncodedCommand).
   Cite: about_pwsh; about_powershell_exe; decode-powershell-command-from-a-running-process; cmd.exe `/c`.

5. **EncodedCommand is an I18 bypass, not the interpreter-dump non-goal.** `node -e 'console.log(process.env.GH_TOKEN)'` only echoes the token `acct exec` already injected — documented non-goal. `pwsh -EncodedCommand <utf16le-b64 of 'gh auth token'>` (or `unset GH_TOKEN; gh auth switch`) is **dumping/mutating gh auth** via a listed I18 shell, with the dangerous words hidden the same way `base64 | sh` was. Treat it as T13/I18, not as `node -e`. Cite: threat-model non-goals; local-acct-exec-deny; about_pwsh EncodedCommand.

6. **Non-goal unchanged** — not a PowerShell parser; not decoding attacker Base64 (fail-closed refuse instead); not sandboxing `node -e` / `python3 -c` env-echo.
