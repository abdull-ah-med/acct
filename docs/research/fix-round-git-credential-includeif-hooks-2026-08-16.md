# Research cites — credential helper quoting, includeIf, hooksPath, host port, GIT_CONFIG_COUNT (2026-08-16)

Fetched before implementation. No memory-only justifications. Primary sources only: git-scm.com man pages, git.git Documentation, git.git source, GHSA.

| Fact | Source |
|------|--------|
| Git **executes credential helpers via the shell**. After transforming the helper string, “the result is executed by the shell.” Config option text: “The resulting string is executed by the shell (so, for example, setting this to `foo --option=bar` will execute `git credential-foo --option=bar` via the shell).” | https://git-scm.com/docs/gitcredentials ; https://raw.githubusercontent.com/git/git/master/Documentation/gitcredentials.adoc |
| Helper string transform: (1) leading `!` → remainder is a **shell snippet**; (2) absolute path → **verbatim** helper string becomes the command; (3) otherwise prepend `git credential-`. Then an operation (`get`/`store`/`erase`) is appended. | https://git-scm.com/docs/gitcredentials (CUSTOM HELPERS) |
| git.git confirms shell invocation: `helper.use_shell = 1` in `run_credential_helper`; `credential_do` concatenates helper + `" %s"` operation. | https://raw.githubusercontent.com/git/git/master/credential.c |
| **Shell quoting is required for whitespace.** Docs: “the arguments are parsed by the shell, so use shell quoting if necessary” with example `helper = "foo --bar='whitespace arg'"` (outer `"` are git-config quotes; inner `'` survive as shell quotes). Absolute-path example is `helper = "/path/to/my/helper --with-arguments"`. | https://git-scm.com/docs/gitcredentials |
| **Git-config quotes are not shell quotes.** `parse_value` treats `"` as a toggle and does not copy it into the value. After parse, `helper = "/path with spaces/x"` is the unquoted string `/path with spaces/x`, which the shell then splits. Backslash escapes (`\"`, `\\`, `\n`, `\t`, `\b`) are applied whether or not the value is quoted. | https://raw.githubusercontent.com/git/git/master/config.c (`parse_value`); https://git-scm.com/docs/git-config (CONFIGURATION FILE → Syntax) |
| Safe helper with spaces: emit a `!` shell snippet with POSIX single quotes (`helper = !'/path with spaces/x'`), **or** put shell quotes *inside* the stored value so they survive config parse (`helper = "\"/path with spaces/x\""`). | https://git-scm.com/docs/gitcredentials (rule 1 + “use shell quoting if necessary”) |
| `includeIf` subsection is a quoted INI subsection: `[includeIf "gitdir:/path/to/foo/.git"]`. “Subsection names are case sensitive and can contain any characters except newline and the null byte. Doublequote `"` and backslash can be included by escaping them as `\"` and `\\`, respectively. Backslashes preceding other characters are dropped when reading; for example, `\t` is read as `t` and `\0` is read as `0`. Section headers cannot span multiple lines.” | https://git-scm.com/docs/git-config ; https://raw.githubusercontent.com/git/git/master/Documentation/config.adoc |
| Unescaped `"` **closes** the subsection. git.git `get_extended_base_var`: after the opening `"`, the next unescaped `"` `break`s the loop; the next character must be `]`. An unescaped `"` in a gitdir path therefore ends the section name. A newline inside the quotes is `error_incomplete_line` (parse failure, not a silent new section). | https://raw.githubusercontent.com/git/git/master/config.c (`get_extended_base_var`) |
| git-config **writer** escapes subsection `"` and `\` when creating a section: `if (key[i] == '"' \|\| key[i] == '\\') strbuf_addch(&sb, '\\');` | https://raw.githubusercontent.com/git/git/master/config.c (`store_create_section`) |
| `includeIf.gitdir:` data is a **glob pattern** (gitignore wildcards plus `**/` / `/**`). If the pattern does not start with `~/`, `./`, or `/`, `**/` is prepended. If it ends with `/`, `**` is added (“matches foo and everything inside, recursively”). `"../"` is not special and matches literally. | https://git-scm.com/docs/git-config (Conditional includes); https://raw.githubusercontent.com/git/git/master/Documentation/config.adoc |
| gitignore glob: `*` matches anything except `/`; `?` one char except `/`; `[a-z]` ranges. “A backslash (`\`) can be used to escape any character.” | https://git-scm.com/docs/gitignore |
| Safe includeIf write: (a) use `git config` so `store_create_section` escapes `"`/`\`; or (b) when writing INI by hand, escape `"` → `\"` and `\` → `\\` in the subsection; reject newline/NUL; start with `/` (or `~/`) so `**/` is not prepended; keep trailing `/` for directory match; treat `*` `?` `[` in the path as glob metacharacters (escape or refuse). | https://git-scm.com/docs/git-config ; https://raw.githubusercontent.com/git/git/master/config.c ; https://git-scm.com/docs/gitignore |
| Value syntax (applies to `user.name`, `user.email`, `credential.helper`, `core.sshCommand`): surrounding whitespace discarded; internal whitespace kept. Leading/trailing whitespace requires `"…"`. Inside quotes, `"` → `\"`, `\` → `\\`. Also recognized: `\n` (NL), `\t` (TAB), `\b` (BS). Other escapes (including octal) are invalid. `#` and `;` start comments to end of line unless quoted. Line continuation: trailing `\`. | https://git-scm.com/docs/git-config (Syntax); https://raw.githubusercontent.com/git/git/master/Documentation/config.adoc |
| `git config` **writes** values escaped: `\n`→`\\n`, `\t`→`\\t`, `"` and `\` get a preceding `\`; wraps in `"` if leading/trailing SP, or if the value contains `;`, `#`, or `\r`. Description: “the value will be escaped.” | https://raw.githubusercontent.com/git/git/master/config.c (`write_pair`); https://git-scm.com/docs/git-config (DESCRIPTION) |
| `core.sshCommand` is “in the same form as the `GIT_SSH_COMMAND` environment variable”. `$GIT_SSH_COMMAND` “is interpreted by the shell, which allows additional arguments to be included.” Paths with spaces in `sshCommand` therefore need **shell** quoting in the stored value, not only git-config quoting. | https://git-scm.com/docs/git-config (`core.sshCommand`); https://git-scm.com/docs/git (`GIT_SSH` / `GIT_SSH_COMMAND`) |
| `core.hooksPath`: default `$GIT_DIR/hooks`. Set to another path (absolute or relative). Relative is “relative to the directory where the hooks are run” (githooks DESCRIPTION: cwd is `$GIT_DIR` if bare, else worktree root). Can disable all hooks with `core.hooksPath=/dev/null` (often via `git -c`). | https://git-scm.com/docs/git-config#Documentation/git-config.txt-corehooksPath ; https://git-scm.com/docs/githooks |
| Config **read order / last-wins**: system → XDG global → `~/.gitconfig` → `$GIT_DIR/config` (local) → worktree → command (`GIT_CONFIG_*` then `-c`). “The files are read in the order given above, with last value found taking precedence over values read earlier.” | https://git-scm.com/docs/git-config (FILES, SCOPES) |
| Writes hit **one file**. Default write is local `$GIT_DIR/config`. `--global` writes only global. “git config will only ever change one file at a time.” `--unset` of a missing key exits 5. | https://git-scm.com/docs/git-config (FILES, DESCRIPTION exit codes) |
| Therefore `git config --global --unset core.hooksPath` **does not** remove a local repo `core.hooksPath`. Local last-wins, so leftover local hooksPath continues to apply. | https://git-scm.com/docs/git-config (FILES last-wins + one-file writes) |
| `host` “includes the port number **if one was specified** (e.g., `example.com:8088`).” Typical `https://example.com/foo.git` example is `host=example.com` with **no** port. `url=https://example.com` “would behave as if `protocol=https` and `host=example.com` had been provided.” | https://git-scm.com/docs/git-credential |
| git.git `credential_from_url_1` copies host as the substring after `://` (or after `@`) up to `/?#`. It does **not** inject default `:443`/`:80`. `https://github.com/` → `host=github.com`. `https://github.com:443/` → `host=github.com:443`. http.c calls `credential_from_url(&http_auth, url)` on the request URL as given. | https://raw.githubusercontent.com/git/git/master/credential.c ; https://raw.githubusercontent.com/git/git/master/http.c |
| Credential contexts compare hosts **exactly** (no parent-domain matching); protocols compared exactly. | https://git-scm.com/docs/gitcredentials (CREDENTIAL CONTEXTS) |
| Allowlist: hostname-only `profile.host` (`github.com`) must accept `host=github.com` (normal clone) and may accept `host=github.com:443` only if the URL **specified** port 443; reject other ports (`:8443`, `:9`). ## Design chosen

1. **Helper paths with spaces** — Keep writing `credential.helper` as a `!` shell snippet with POSIX single-quoting of the absolute shim path (`helper = !'/path with spaces/git-credential-acct'`). That is rule (1) in gitcredentials and survives git-config quote stripping. Do not write a bare absolute path with only git-config `"` wrapping; those quotes are stripped and the shell splits on spaces. Continue emitting `helper = ""` immediately before the acct helper in both the global managed block and each profile `.inc`.

2. **includeIf gitdir quoting** — When interpolating `[includeIf "gitdir:…"]` (or `gitdir/i`) by hand, escape `"` → `\"` and `\` → `\\` in the path (same as `store_create_section`). Reject binding paths that contain newline, NUL, or unescaped glob metacharacters `*` `?` `[` (gitdir is a glob). Keep absolute paths with a trailing `/` so Git matches the directory tree and does not prepend `**/`.

3. **INI value escaping for profile fragments** — When writing `user.name` / `user.email` / `credential.helper` / `core.sshCommand` into `.inc` files, apply git-config value rules: wrap in `"` if the value has leading/trailing space or contains `#` `;`; escape `"`, `\`, NL, TAB. Continue rejecting `"`, `\`, CR, LF, NUL in profile name/email/host (fail closed) so include fragments cannot break out of INI. `core.sshCommand` additionally needs **shell** quotes around the key path (`GIT_SSH_COMMAND` is shell-interpreted).

4. **hooksPath uninstall** — `git config --global --unset core.hooksPath` only touches the global file and leaves local `$GIT_DIR/config`. Uninstall must: (a) `--global --unset` if global value is the acct hooks dir; (b) for each binding path (and cwd if a repo), `git -C <toplevel> config --local --get core.hooksPath` and `--local --unset` **only** when the value is the acct hooks directory. Do not unset a third-party local hooksPath. Local last-wins, so leftover local acct hooksPath would keep enforce hooks after “uninstall.”

5. **Host allowlist** — `https://github.com/` → `host=github.com` (no port). `https://github.com:443/` → `host=github.com:443`. Hostname-only profile: allow bare host or `:443` only; reject other ports. Profile `github.com:443`: require exact `host=github.com:443` (do not treat bare `github.com` as a match — Git compares hosts exactly). Continue rejecting empty/blank host and missing protocol (CVE-2020-11008 class).

6. **GIT_CONFIG_COUNT** — Treat as command-scope config that **does** apply to `git clone` (and every other Git command that loads config). It can inject `credential.helper`, `core.hooksPath`, `user.*`, etc. for that process. Do not assume it persists into the new repo’s `.git/config`. Doctor/exec hardening that already considers `git -c` should treat `GIT_CONFIG_COUNT` the same family (command scope, overrides files).

7. **Empty helper `""`** — Still required. Multi-valued `credential.helper` cannot be unset otherwise; empty string clears the list (24321375, still in master and gitcredentials). Keep `helper = ""` then acct helper in global block and in every profile include.

8. **CVE-2020-11008** — acct helper must refuse `get` when `host` is missing, empty, whitespace-only, or contains newline/NUL/`%0a`/`%0d`, and when `protocol` is missing. Do not return a password for a wildcard pattern. Git’s own refuse-missing-host is defense in depth; helpers not on the GCM-for-Windows “known safe” list are assumed vulnerable if they wildcard-match blank fields.

## Confirmed behaviors

- Helpers run via the shell (`use_shell = 1`); git-config `"` wrapping is stripped before the shell sees the command.
- `helper = ""` still clears the helper list (24321375 code path still in master).
- includeIf subsection `"` must be escaped; newline/NUL cannot appear in subsection names; unescaped `"` closes the section.
- gitdir patterns are globs; trailing `/` means “this directory and everything under it.”
- Local config beats global; `--global --unset` cannot remove local `core.hooksPath`.
- Default HTTPS URL **without** an explicit port yields `host=github.com`, not `host=github.com:443`.
- `GIT_CONFIG_COUNT` is command-scope runtime config and is loaded for ordinary Git commands including clone.
- CVE-2020-11008 class: blank host/protocol must not yield credentials. store/cache/osxkeychain were the documented triggers.

## Unknowns

- Whether some third-party HTTP stacks or older Git+curl paths ever add `:443` to `host` when the URL omitted the port. Official docs and current `credential_from_url_1` / http.c do **not** inject it. Allowing `:443` for hostname-only profiles remains a conservative extra accept, not a documented default.
- Exact glob-escape interaction when a backslash appears both as INI subsection escape and as gitignore glob escape (double encoding). Safer to refuse `*` `?` `[` `\` in binding paths than to invent a dual-escape scheme without a git.git test cited here.
- Whether `git clone` copies any `GIT_CONFIG_*` keys into the new repo (docs describe runtime override only; not verified by reading builtin/clone.c in this pass).
- GCM-for-Windows “known safe” status is from the 2020 advisory; this pass did not re-audit current GCM source.

## Recommended fix for acct (concrete)

1. **Keep** `quoteHelper` as `!` + POSIX single-quote (`includeIf.ts`). Do not switch to bare absolute `helper = "/path with spaces/…"`.
2. **Keep** `helper = ""` before every acct helper (global block + profile `.inc`). Still required (gitcredentials + 24321375 + master `credential.c`).
3. **Escape includeIf subsections** in `buildIncludeIfBlock`: apply `store_create_section` rules (`"`/`\` backslash-escaped) before interpolating `[includeIf "gitdir/i:…"]`. Reject binding paths with NL/NUL/`*`/`?`/`[`.
4. **Quote INI values** in `renderProfileInclude` for `user.name` / `user.email` / helper / `sshCommand` using `write_pair` rules if any rejected-char policy is relaxed; until then keep fail-closed field validation (`profile-fields.ts`).
5. **Uninstall hooksPath**: after `--global --unset`, walk `config.bindings` (and cwd) and `--local --unset core.hooksPath` iff the value equals the acct hooks directory. Cite FILES last-wins + one-file writes.
6. **Keep** `hostAllowed`: hostname-only → bare or `:443`; pinned port → exact match only. Cite git-credential “if one was specified” + exact host compare.
7. **Keep** `isSafeHost` empty/newline/`%0a` reject (GHSA-hjc9-x69f-jqj7). Also refuse missing `protocol` on `get`.
8. **Treat `GIT_CONFIG_COUNT` as `git -c`** for clone/exec/doctor: command-scope overrides files; can install a competing helper for that process.
